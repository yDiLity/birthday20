# Праздничная «Своя игра» — Telegram-бот

Бот для дня рождения: именинник отвечает на 12 вопросов (по 3 варианта), после каждого ответа бот присылает текст-реакцию и вертикальное видео, в финале — общее видеопоздравление. Всё происходит в групповом чате, видят все.

Спецификация — [PRD.md](PRD.md). Реализация полностью ей соответствует.

## Структура

```text
api/telegram.js        вебхук: читает raw body, отдаёт апдейт в telegraf, всегда отвечает 200
api/warm.js            тёплый пинг (cron), чтобы функция не засыпала
api/index.js           страница-заглушка «бот работает»
src/bot.js             вся логика: игра, кнопки, админка, редактор контента, тесты по кодам
src/content.js         загрузка content/questions.json + слой правок (override), флэттен вопросов
src/quizzes.js         персональные тесты: модель, проверка, коды, шаблоны
src/store.js           Redis (Upstash): сессии, правки контента, тесты, черновики + fallback в память
src/config.js          переменные окружения, проверка настроек
content/questions.json сценарий: категории, вопросы, реакции, финал
scripts/webhook.js     setWebhook / getWebhookInfo / deleteWebhook / getMe
scripts/smoke.js       проверка контента и хранилища
scripts/e2e.js         полный прогон игры через фейковый Telegram API
scripts/api-check.js   проверка серверless-обработчика
```

## Нужно от тебя (2 минуты)

1. **@BotFather** → `/newbot` → получи токен.
2. Узнай свой Telegram ID: напиши боту `@userinfobot` (или после деплоя команду `/admin_id`).
3. Задай **имя именинника** — после деплоя прямо в боте: `/admin_edit` → 👤 Имя именинника. Либо сразу переменной `HERO_NAME` в Vercel.

Upstash Redis — необязателен, проект работает и без него (об этом ниже).

## Настройка переменных

Скопируй `.env.example` в `.env.local` (для локальных скриптов) и продублируй те же значения в **Vercel → Settings → Environment Variables**:

| Переменная | Обязательна | Смысл |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_ID` | да | твой Telegram ID для админки (можно `ADMIN_IDS=1,2,3`) |
| `HERO_ID` | нет | Telegram ID именинника; если пусто — игру может начать любой, кто напишет `/start` |
| `HERO_NAME` | нет | имя по умолчанию. Без Redis лучше задать здесь: правкой в админке имя слетит при перезапуске |
| `ALLOW_RESTART` | нет | `true` — после финала можно пройти заново (по умолчанию `true`) |
| `SESSION_TTL_DAYS` | нет | TTL сессии в Redis (по умолчанию 7 дней) |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | нет | без них всё живёт в памяти — см. «Без Upstash» |
| `UPSTASH_REDIS_REST_URL` | желательно | Redis для сохранения прогресса между холодными стартами |
| `UPSTASH_REDIS_REST_TOKEN` | желательно | второй ключ Redis |
| `WEBHOOK_URL` | для скрипта | `https://<твой-проект>.vercel.app/api/telegram` |

Без Redis бот не падает: сессия живёт в памяти функции и сбрасывается при холодном старте (в логах будет предупреждение).

## Деплой на Vercel

### Вариант 1. Через консоль (быстро)

1. Залей проект в Git-репозиторий (GitHub/GitLab).
2. [vercel.com](https://vercel.com) → Add New → Project → импортируй репозиторий.
3. Framework Preset: **Other**. Build Command: `npm install`. Output Directory: оставь пустым.
4. В **Environment Variables** добавь все переменные из таблицы выше.
5. Deploy. Запомни домен вида `my-bot.vercel.app`.

### Вариант 2. Через CLI

```bash
npm install
npx vercel            # первый деплой, создаст проект
npx vercel --prod     # продакшн
```

Файл `vercel.json` уже содержит нужное: функция `api/telegram.js` включает `content/questions.json` в сборку, cron пингует `/api/warm` раз в сутки.

### Проверка, что функция жива

Открой в браузере `https://<твой-проект>.vercel.app/api/telegram` — должен вернуться JSON со статусом бота и списком проблем (если что-то не задано).

## Настройка webhook

Локально (в `.env.local` должны быть `BOT_TOKEN` и `WEBHOOK_URL`):

```bash
npm run webhook        # setWebhook + getWebhookInfo
npm run webhook:info   # проверить, что Telegram видит webhook
npm run webhook:delete # снять webhook (например, перед vercel dev)
npm run bot:info       # getMe — проверить токен
```

`vercel dev` работает только с webhook через туннель (`vercel dev` пробрасывает URL наружу сам — используй выданный им адрес в `WEBHOOK_URL`).

Если webhook слетел после передеплоя — просто запусти `npm run webhook` ещё раз.

## Редактор контента: менять тексты и видео прямо в боте

Всё редактируется из Telegram, redeploy не нужен. Правки лежат в Redis отдельным ключом `content:overrides` и **перекрывают** `content/questions.json` (JSON остаётся как база и как «Reset»).

### Кнопки (для именинницы — мамы)

1. Открой бота в личке → `/admin`.
2. Нажми **✏️ Редактировать контент** → `/admin_edit`.
3. Выбери, что меняем: текст вопроса, вариант ответа, реакцию, видео, приветствие, финальный текст, финальное видео, текст-заглушку.
4. Выбери вопрос → вариант (если нужно) → просто **пришли новый текст сообщением**. Готово, бот подтвердит и покажет результат.

Для видео работает то же самое: после выбора вопроса и варианта пришли `file_id` (или сначала отправь видео боту в личку — он вернёт `file_id` готовой командой).

### Те же правки командами (быстрее, если знаешь, что менять)

| Команда | Пример |
|---|---|
| `/admin_q <q_id> text <новый текст>` | `/admin_q q1 text Как ты представляешь idealный праздник?` |
| `/admin_q <q_id> label <А/Б/В> <новый вариант>` | `/admin_q q1 label А Шумная вечеринка` |
| `/admin_q <q_id> reaction <А/Б/В> <новая реакция>` | `/admin_q q1 reaction А Значит, сегодня будет громко!` |
| `/admin_set <поле> <текст>` | `/admin_set greeting Салют, {name}!`, `/admin_set final_text ...`, `/admin_set no_video ...` |
| `/admin_video <q_id> <А/Б/В> <file_id>` | `/admin_video q1 А BAACAgIAAx...` |
| `/admin_video final video <file_id>` | `/admin_video final video BAACAgIAAx...` |
| `/admin_list` | какие ключи сейчас перекрыты + каких видео не хватает |
| `/admin_export` | весь актуальный контент + ключи правок файлом `content-backup.json` |
| `/admin_reset_content` | снести все правки и вернуться к `content/questions.json` |

Кнопка «Всё к JSON» спрашивает подтверждение (и показывает, сколько правок сбросит), команда `/admin_reset_content` сбрасывает сразу. Перед сбросом можно выгрузить всё в файл: `/admin_export`.

`{name}` и `{count}` в текстах подставляются автоматически.

### Важно про Redis

Правки контента хранятся в том же Redis, что и сессии. **Без Upstash Redis они не переживут холодный старт** (останутся только в тёплой памяти функции). Поставь Upstash до праздника — тогда и прогресс, и правки сохраняются.

## Персональные тесты: сделал в личке — запустил в группе кодом

Это отдельные тесты, не связанные с основной игрой. В личке собираешь тест пошагово, бот выдаёт **код из 6 цифр**. В группе отправляешь этот код — бот запускает именно этот тест. Отвечает тот, кто отправил код, или именинник, и **все в чате видят каждый ответ**.

### Как сделать тест (нужны права `ADMIN_ID`)

1. Открой бота в личке → `/newtest`.
2. Выбери откуда взять вопросы:
   - **📋 Копия основной игры** — все 12 вопросов, реакции и видео уже на месте;
   - **🎓 Про именинника** — заготовка на 10 вопросов, меняешь под себя;
   - **🆕 С нуля** — бот спросит название, потом вопросы по одному.
3. По каждому вопросу: текст → варианты А/Б/В → реакции → видео-реакции.
   - Реакцию и видео можно пропустить кнопкой (реакция станет `Ответ: <вариант>`).
   - Видео можно не вставлять `file_id`, а **прислать само видео** — бот подставит.
4. «➕ Ещё вопрос» — добавить вопрос, «✏️ Править вопрос» — выбрать любой и переписать.
5. **💾 Сохранить и получить код** — бот ответит кодом. Он действует постоянно, пока тест не удалён.

Командные помощники: `/newtest_preview` (черновик текстом), `/newtest_save`, `/newtest_cancel`, `/mylist` (твои тесты с кодами и кнопкой удаления).

### Как запустить в группе

Отправь в группу с ботом просто код:

```text
482913
```

Бот напишет, что запускает тест «{название}», и начнёт задавать вопросы. В финале — сводка «Ваши ответы: 1. А. …, 2. В. …».

| Ситуация | Что делать |
|---|---|
| Ответить другой участник | нельзя: кнопки нажимает автор кода или именинник |
| В чате уже идёт другой тест | сначала `/test_stop` |
| Пройти заново | кнопка «🔁 Пройти ещё раз» |
| Остановить досрочно | `/test_stop` (автор, именинник или админ) |
| Код не подошёл | бот молчит: это просто число в чате |

Тесты лежат в Redis (`bdq:quiz:<код>`), активный тест в чате — `bdq:personal:<chat_id>`, черновик мастера — `bdq:draft:<user>:<chat>` (6 часов). Без Redis тесты не переживут холодный старт.

## Без Upstash: что нужно знать

Redis можно не настраивать — бот запустится и отработает. Но Vercel держит функцию в памяти, пока идут запросы, и перезапускает её, когда трафик стихает. Всё, что не лежит в базе, в этот момент забывается.

**Будет работать:** сама игра (вопросы, варианты, реакции, видео, финал), приём `file_id` из лички, `/admin_status`, `/admin_preview`, `/admin_export`.

**Может слететь:** начатая сессия (придётся снова `/start`), собранные ответы в финальной сводке, правки текстов и вопросов из админки, имя именинника из админки, персональные тесты по кодам.

**Что делать, чтобы не потерять важное:**
- имя именинника задай переменной `HERO_NAME` в Vercel (не кнопкой в админке) — оно переживёт любой перезапуск;
- тексты и вопросы перед праздником проверь и, если что-то правил в боте, перенеси в `content/questions.json` и задеплой через Git — тогда они в коде и не пропадут;
- держи игру в одном «заходе»: чтобы сессия не слетела посреди праздника, не давай боту долго простаивать;
- `/admin_status` сам предупредит, если Redis не настроен.

Если Upstash понадобится позже: [console.upstash.com](https://console.upstash.com) → Create database → добавить `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` в Vercel → Redeploy. Ничего в коде менять не нужно.

## Имя именинника — задаётся в админке

`HERO_NAME` в env теперь необязателен: имя меняется прямо в боте и хранится в Redis (`bdq:settings`), поэтому работает сразу и переживает холодный старт.

| Шаг | Действие |
|---|---|
| Кнопкой | `/admin_edit` → **👤 Имя именинника** → пришли имя текстом |
| Командой | `/admin_name Игорь` |
| Посмотреть | `/admin_status` → строка `Именинник: Игорь` |
| Проверить | `/admin_preview` — в текстах будет новое имя |

Под `{name}` подставляется в приветствие и финальный текст. Уже начатые игры сохраняят имя, которое было при запуске. Если Upstash не настроен, имя живёт только в памяти — тогда надёжнее задать `HERO_NAME` в Vercel, а кнопку использовать для проверки текстов.

## Загрузка видео и получение file_id

1. Открой бота в личке и отправь видео (5–10 секунд, вертикальное).
2. Бот ответит `file_id` и готовой командой.
3. Скопируй команду и отправь её в чат с ботом (в группу или в личку):

```text
/admin_video q1 А BAACAgIAAx...
/admin_video final video BAACAgIAAx...
```

4. Проверь, сколько видео загружено: `/admin_status` — покажет `Видео: 12/37` и список недостающих.

Альтернатива: вписать `file_id` прямо в `content/questions.json` и задеплоить — тогда видео переживёт сброс Redis и `/admin_reset_content`.

**Всего нужно 37 видео:** 12 вопросов × 3 варианта + 1 финальное. Если не успеваешь — 37 можно сократить: сначала загрузи по одному видео на вопрос (12) и переиспользуй их между вариантами, а к празднику дозагрузи остальные.

### Как залить пачкой и не ошибиться

- `/admin_preview` — весь сценарий текстом в чат: видно, что и в каком порядке идёт.
- `/admin_status` — список `q1:А, q1:Б, …` того, чего не хватает.

## Как это работает

```text
Telegram → /api/telegram (Vercel) → telegraf → Redis (сессия + правки контента)
                                  └── content/questions.json (базовый контент)
```

- Кнопка ответа: `opt:<индекс_вопроса>:<индекс_варианта>`, кнопка «дальше»: `next:<индекс_вопроса>`. Индекс в данных проверяется, поэтому старые кнопки и повторные нажатия не ломают игру.
- На каждый вопрос — ровно один записанный ответ: второй вариант после выбора игнорируется.
- Контент = `content/questions.json` + правки из Redis (`content:overrides`). Приоритет у правки, поэтому редактор работает без redeploy.
- Видео-`file_id` тоже лежат в Redis (ключи вида `q:q1:video:А`, `final:video`), TTL — год, переживает деплой.
- Если видео не загружено или Telegram его не отдал — бот пишет заглушку и продолжает, игра не ломается.
- Финал: видео + текст + кнопка «Играть снова» (если `ALLOW_RESTART=true`).

## Если что-то пошло не так

| Симптом | Причина и лечение |
|---|---|
| Бот молчит | Нет webhook: `npm run webhook:info`, затем `npm run webhook` |
| `401 Unauthorized` в логах | Неверный `BOT_TOKEN` |
| `getWebhookInfo: url неверный` | `WEBHOOK_URL` без `/api/telegram` или без https |
| `Redis: недоступен` в `/admin_status` | Проверь обе переменные Upstash; игра работает, но прогресс может сброситься |
| Видео не отправляется | `file_id` из другого бота или битый — загрузи видео заново; временно работает заглушка |
| Имя в текстах не то | `/admin_edit` → 👤 Имя именинника → пришли имя текстом (или `/admin_name Игорь`) |
| Правки пропали после redeploy/холодного старта | Не настроен Upstash Redis — поставь `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` |
| `/admin_list` показывает «Правок нет», а текст старый | Правки не сохранились: проверь Redis (см. выше) или отредактируй `content/questions.json` |
| Гость жмёт кнопки | Именинник отвечает только в своей сессии: проверь `HERO_ID` |
| Код из 6 цифр в группе не запускает тест | Тест удалён (`/mylist`) или не хватает `ADMIN_ID` при создании; проверь, что код состоит только из цифр |
