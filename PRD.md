# PRD: Telegram-бот «Праздничная "Своя игра"» для именинника

## 0. Резюме проекта

**Что делаем:** Telegram-бот, который в день рождения устраивает имениннику (мужчина, 40–42 года) интерактивную игру в стиле «Своей игры». Бот добавляется в групповой чат, все участники видят ответы. Именинник проходит фиксированную цепочку вопросов, на каждый — 3 варианта ответа. После выбора бот присылает текст-реакцию + вертикальное видео однокурсницы (5–10 сек). В финале — одно общее видеопоздравление.

- **Срок:** сегодня.
- **Хостинг:** Vercel (serverless + webhook).
- **Хранилище состояния:** Upstash Redis.
- **Админка:** команды прямо в боте.
- **Видео:** `file_id`, загруженные в бота вручную.

## 1. Цели и принципы

1. **Персонализация:** каждый ответ = личная реакция и видео.
2. **Вовлечённость:** именинник активно играет, а не смотрит.
3. **Публичность:** всё происходит в групповом чате, все видят.
4. **Простота:** ровно 3 варианта на вопрос, никаких баллов, никаких возвратов.
5. **Надёжность:** бот не должен падать, состояние сохраняется в Redis.
6. **Скорость:** сценарий и код — за один день.

## 2. Участники и роли

| Роль | Кто | Что делает |
|---|---|---|
| Именинник | мужчина 40–42 | Нажимает кнопки, проходит игру |
| Однокурсницы | женщины | Записывают вертикальные видео 5–10 сек |
| Организатор (ты) | владелец бота | Создаёт бота, загружает видео, управляет через `/admin` |
| Гости чата | все в группе | Наблюдают за игрой |
| Бот | Telegram-бот | Ведёт игру, отправляет реакции и видео |

## 3. Сценарий и контент

### 3.1. Структура

| Элемент | Количество |
|---|---|
| Категорий | 5 |
| Вопросов | 12 (варьируемо 10–12) |
| Вариантов ответа на вопрос | ровно 3 |
| Видеореакций | 3 на каждый вопрос (по одной на вариант) |
| Финальное видео | 1 общее |
| Порядок вопросов | фиксированный |
| Возврат назад | невозможен |
| Ожидание ответа | бесконечное |

### 3.2. Категории (черновые)

- **«Идеальный день»** — про формат праздника.
- **«Ты и мы»** — про общение, дружбу, привычки.
- **«Планы на год»** — про мечты и цели.
- **«Воспоминания»** — про учёбу и общие моменты.
- **«Сюрпризы»** — неожиданные и шуточные вопросы.

### 3.3. Формат вопроса

1. Текст вопроса.
2. 3 inline-кнопки: А / Б / В.
3. Для каждого варианта:
   - `reaction_text` — короткая шутка/комментарий (1–2 строки, эмодзи умеренно).
   - `video_file_id` — видео однокурсницы.
4. После видео — кнопка «Следующий вопрос 🎯».
5. После последнего вопроса — финальное видео.

## 4. Техническая архитектура

### 4.1. Стек

| Компонент | Решение | Почему |
|---|---|---|
| Runtime | Node.js 20 | Vercel Serverless Functions |
| Telegram-библиотека | telegraf | Лёгкая, поддерживает webhook |
| Хостинг | Vercel | Бесплатно, быстро, serverless |
| Состояние | Upstash Redis | Бесплатный tier, работает с Vercel |
| Контент | JSON в репозитории | Просто, версионируется |
| Видео | `file_id` Telegram | Не храним файлы, только ID |
| Админка | Команды в боте | Быстро, без отдельного фронта |

### 4.2. Схема работы

```text
Telegram → webhook → Vercel Function → Telegraf → Redis (сессия)
                                          ↓
                                    JSON-контент (вопросы, видео)
```

### 4.3. Почему webhook, а не polling

- Vercel — serverless, не держит процесс.
- Webhook — Telegram сам стучится на URL функции.
- Функция просыпается, обрабатывает, засыпает.

### 4.4. Хранение состояния

- **Ключ:** `session:{chat_id}:{user_id}`.
- **Значение:** `{ current_question_index, answers: [...], finished: bool }`.
- **TTL:** 7 дней (чтобы не мусорить).

## 5. Логика работы бота

### 5.1. Запуск

1. Бот добавлен в групповой чат.
2. Именинник пишет `/start` (или команду запуска).
3. Бот отправляет приветствие и первый вопрос.
4. Все в чате видят.

### 5.2. Прохождение

1. Именинник нажимает вариант (А/Б/В).
2. Бот:
   - фиксирует ответ в Redis;
   - отправляет `reaction_text`;
   - отправляет видео (`file_id`);
   - показывает кнопку «Следующий вопрос 🎯».
3. Именинник нажимает кнопку — бот отправляет следующий вопрос.
4. Цикл повторяется до последнего вопроса.

### 5.3. Финал

1. После последнего ответа бот отправляет финальное видео.
2. Отправляет короткое текстовое завершение (опционально).
3. Сессия помечается `finished: true`.
4. Повторный `/start` — либо «игра уже пройдена», либо перезапуск (по твоему выбору).

### 5.4. Ограничения

- Возврат назад невозможен.
- Ожидание ответа — бесконечное.
- Баллов нет.
- Только именинник может нажимать кнопки (проверка по `user_id`).

## 6. Админка (в боте)

### 6.1. Команды

| Команда | Действие |
|---|---|
| `/admin` | Меню администратора (только для твоего Telegram ID) |
| `/admin_status` | Кто прошёл, на каком вопросе, сколько ответов |
| `/admin_video <q_id> <option> <file_id>` | Заменить видео для варианта |
| `/admin_reset <chat_id>` | Сбросить сессию |
| `/admin_preview` | Прогнать сценарий без видео (текстом) |

### 6.2. Ограничения

- Доступ только по Telegram ID организатора.
- Все изменения пишутся в Redis (или в JSON, если нужна персистентность между деплоями).

## 7. Контент: что готовим

### 7.1. Видео

- Вертикальные, 5–10 сек.
- Записывают однокурсницы.
- По одному на каждый вариант ответа (12 вопросов × 3 = 36 видео).
- Плюс 1 финальное общее видео.
- **Итого: 37 видео.**

### 7.2. Как загрузить видео и получить `file_id`

1. Открыть бота в личке.
2. Отправить видео.
3. Бот (или ты вручную через `@userinfobot` / логи) получает `file_id`.
4. Вписать `file_id` в JSON или через `/admin_video`.
5. Если 37 видео — много, можно сократить до 10 вопросов (30 видео) или переиспользовать видео между вариантами.

### 7.3. Тексты

- 12 вопросов.
- 36 реакций (по 3 на вопрос).
- 1 финальный текст.
- Приветствие.
- Тексты кнопок.

| Риск | Решение |
|---|---|
| Vercel cold start | Тёплый пинг раз в 5 мин (cron) |

| Видео не загружено | Заглушка-текст вместо видео |
